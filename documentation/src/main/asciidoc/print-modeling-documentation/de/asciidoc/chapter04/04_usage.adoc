[#print_model_usage]
= Verwendung des Print Model

Wenn das Print Model korrekt modelliert und die Print Engine ordnungsgemäß in die A12-Full-Stack-Anwendung integriert wurde (link:/docs/PRINT_ENGINE/print-technical-documentation/index.html#a12_fullstack_integration[A12 Fullstack Integration]),
können Form Models oder Overview Models zum Starten des Druckvorgangs verwendet werden:

. link:/docs/SME/sme-fm-ba-docs/index.html#txt:detail:button[Form Model Event Button]:
Erstellen Sie einen Event Button im Form Model mit dem Eventnamen *event_print* und einer Annotation mit dem Namen *print_model*, die den Namen des Print Model als Wert enthält.
. link:/docs/SME/sme-om-ba-docs/index.html#row-action[Overview Model Row Button]: Erstellen Sie einen Row Action Event Button im Formular mit dem Eventnamen *event_print* und einer Annotation mit dem Namen *print_model*, die den Namen des Print Model als Wert enthält.

In einem Formular in der link:/docs/overall/preview_app/index.html[Preview App] wird das Dokument vor dem Drucken automatisch validiert und gespeichert, um sicherzustellen, dass die aktuellen Werte im PDF enthalten sind.

Während des Druckvorgangs im Formular und in der Overview in der link:/docs/overall/preview_app/index.html[Preview App] wird ein Lade-Spinner über die gesamte Anwendung hinweg angezeigt.

Damit statische Bilder und benutzerdefinierte Schriftarten im von der Preview App generierten PDF korrekt dargestellt werden, müssen sie in bestimmten Ordnern abgelegt sein:

* Statische Bilder: `resources/static-images`
* Benutzerdefinierte Schriftarten: `resources/fonts`

[CAUTION]
====
Das Print Model selbst kann aktualisiert werden, während die Preview App läuft. Für statische Bilder und Schriftarten gilt dies derzeit jedoch nicht. Wenn dem Print Model ein neues statisches Bild oder eine neue Schriftart hinzugefügt wird, muss die Preview App daher aktuell neu gestartet werden.
