= Listing [[Listing]]

Das Listing-Element fügt eine tabellarische Darstellung eines bestimmten Teilbaums eines Dokuments in das resultierende PDF ein.
Jede Zeile der generierten Tabelle entspricht einer Field- oder Group-Instanz des ausgewählten Dokuments.

[NOTE]
====
Aufgrund der Komplexität der Anpassungsmöglichkeiten wird das Listing-Element für erfahrenere Benutzer empfohlen.

Ziehen Sie in Betracht, eine <<Table, Table>> zu modellieren, wenn der Anwendungsfall dies zulässt.
====

Die Spalten der Tabelle werden am Listing-Element konfiguriert.
Der Zellinhalt und die Stile werden durch link:/docs/KERNEL/kernel-documentation-ba-en/index.html[A12 Kernel-Berechnungen] definiert, die in der jeweiligen Spaltenkonfiguration festgelegt werden.
Diese Berechnungen werden auf der jeweiligen Field- oder Group-Instanz der Zeile ausgeführt, um die Ergebniswerte zu ermitteln.

Document Model:: Wählen Sie ein Document Model aus, das im <<SchemaTab, Schema Tab>> referenziert wird.
Group:: Der Path zur Group im Document Model, die den Root des Table Elements definiert.
Diese Group sowie jede darin enthaltene Group oder jedes darin enthaltene Field erzeugt eine Zeile in der resultierenden Tabelle.
Columns:: Jede Spalte des Table Elements gehört zu einem definierten verschachtelten Element.
Klicken Sie auf „Add", um neue Spalten hinzuzufügen, oder klicken Sie auf die Spalte in der Tabelle, um sie zu bearbeiten.
Siehe <<ListingColumn>> für weitere Details.
Row Property Computations:: Es können Property Computations modelliert werden, die auf jede Zeile des Listings angewendet werden. Siehe <<PropertyComputation>> für weitere Details.
Group Property Computations:: Es können Group Property Computations modelliert werden, die auf die ausgewählte Group-Instanz angewendet werden. Siehe <<GroupPropertyComputation>> für weitere Details.

Darüber hinaus ist das Listing-Element über <<BorderProperties, Border Properties>> sowie separate Konfigurationen der <<TextProperties, Text Properties>> für Header und Body des Listings konfigurierbar.

image::chapter03/03_listing_detail_view.png[Detailansicht des Listing-Elements,title="Detailansicht des Listing-Elements",width=415.13]

== Listing-Spalten [[ListingColumn]]

Column label:: Das Label der Spalte im Header des Table Elements.
Siehe <<InputSource>> für weitere Details zu diesen Einstellungen.
+
* *Default Value*
* *User Input*
* *Unset Value*
Column Width:: Prozentuale Breite der Spalte in Bezug auf die Breite des Listing-Elements.
Wenn keine Breite angegeben ist, wird das Standard-HTML-Tabellenverhalten angewendet.
Der Wert muss eine Ganzzahl zwischen 1 und 100 sein.
Die Summe aller Breiten wird ebenfalls validiert, um sicherzustellen, dass sie 100 oder weniger beträgt.
Sort group content by this column:: Die resultierenden Tabellenzeilen werden nach dem Inhalt dieser Spalte sortiert.
+
[NOTE]
====
Die Verschachtelungsstruktur des A12-Dokuments bleibt bei der Sortierung erhalten.
Die Inhalte jeder Group werden gemäß der Sortierung umstrukturiert, aber keine Instanz innerhalb einer Group wird nach außen verschoben.
====
Column has custom text properties:: Ermöglicht die vollständige Konfiguration der <<TextProperties, Text Properties>> für die aktuelle Spalte.
Die Text Properties werden am unteren Rand des Listing Column Editors angezeigt.

Column has custom border properties:: Ermöglicht die vollständige Konfiguration der <<BorderProperties, Border Properties>> für die aktuelle Spalte.
Die Border Properties werden am unteren Rand des Listing Column Editors angezeigt.

=== Default Computations [[ListingDefaultComputation]]

Ein Satz von <<ValueComputations, Value Computations>> und <<PropertyComputation, Property Computations>>, die ausgeführt werden, wenn weder <<ListingGroupComputation,Group Computations>> noch <<ListingFieldComputation,Field Computations>> für die jeweilige Instanz der Zeile zutreffen.

Value Computations:: Eine Computation Table wird modelliert, um unter bestimmten Bedingungen einen bestimmten Wert zurückzugeben.
Siehe <<ValueComputations>> für weitere Details.

Property Computations:: Es können Property Computations modelliert werden, die auf jede Zeile dieser Listing-Spalte angewendet werden. Siehe <<PropertyComputation>> für weitere Details.

image::chapter03/03_listing_column_detail_view.png[Detailansicht der Listing-Spalte,title="Detailansicht der Listing-Spalte",width=400]

=== Group Computations [[ListingGroupComputation]]

Ein Satz von <<ValueComputations, Value Computations>> und <<PropertyComputation, Property Computations>>, die auf jede Zeile angewendet werden, die einer Group-Instanz entspricht.

=== Field Computations [[ListingFieldComputation]]

Ein Satz von <<ValueComputations, Value Computations>> und <<PropertyComputation, Property Computations>>, die auf jede Zeile angewendet werden, die einer Field-Instanz entspricht, deren Field Type mit dem Document Field Type übereinstimmt.

Select the field type of the results of the value computations:: Erwarteter Eingabe-Field-Type für die Field Value Computation.

Computation Output Type:: Erwarteter Ausgabe-Field-Type für die Field Value Computations.
Die Ausgabe der Value Computation sollte diesem Field Type entsprechen.

Field Type:: Die Formatierung kann basierend auf dem Field Type der Instanz angepasst werden, indem einer der folgenden Typen ausgewählt wird:
+
* *HTML:* Formatiert eine Field-Instanz, die HTML-Inhalte enthält. HTML-Tags werden verarbeitet und im resultierenden PDF gerendert.
+
--
Die folgenden HTML-Tags werden unterstützt:

`<p>`, `<span>`, `<strong>`, `<em>`, `<u>`, `<br>`

Die folgenden CSS-Eigenschaften werden in `style`-Attributen unterstützt:

* `color` – jeder gültige Hex-Farbwert (z.{nbsp}B. `#ff0000`)
* `background-color` – jeder gültige Hex-Farbwert (z.{nbsp}B. `#ff0000`)
* `text-align` – `left`, `right`, `center`, `justify`

[CAUTION]
====
Nicht unterstützte Tags und CSS-Eigenschaften werden beim Rendern stillschweigend entfernt.
====
--
* *Date:* Formatiert eine Date-Field-Instanz in ein lesbares Datumsformat basierend auf der Locale. Die Formatierung kann durch Definition eines bestimmten Musters für die Auswertung angepasst werden. Beispielsweise wird das Muster `YYYY.MM.dd` zu z.{nbsp}B. `2025.02.17` ausgewertet, während das Muster `dd'th of' MMMM YYYY 'at' HH:mm 'o''clock'` zu `17th of February 2025 at 13:54 o'clock` ausgewertet wird.
* *Date range:* Formatiert eine DateRange-Field-Instanz in ein lesbares Format basierend auf der Locale. Die Formatierung des Startdatums, Enddatums und Trennzeichens kann durch Definition eines Auswertungsmusters angepasst werden.
+
[NOTE]
====
Ausführlichere Informationen zu Auswertungsmustern für Datumsangaben finden Sie durch Klicken auf das Info-Symbol neben dem Mustereingabefeld oder in der
https://docs.oracle.com/javase/8/docs/api/java/time/format/DateTimeFormatter.html[offiziellen Java-Dokumentation].
====
+
* *Checkbox:* Formatiert eine Boolean-Field-Instanz basierend auf ihrem Wert. Sie können festlegen, welcher Wert für `true` und `false` angezeigt werden soll.
+
[NOTE]
====
Um Sonderzeichen wie ☐ oder ☑ als Anzeigewert für den Checkbox-Typ darzustellen, stellen Sie sicher, dass der ausgewählte <<TextStylesTab, Text Style>> eine Schriftart verwendet, die diese Zeichen unterstützt.
Der Print Model Editor stellt die Schriftart <<DefaultFonts, Noto Sans Symbols>> bereit, die mit diesen Symbolen kompatibel ist.
====

Suffix:: Modellieren Sie ein Suffix für die formatierten Zeichenkettendaten.

== Value Computations [[ValueComputations]]
Zusätzlich zu den Operatoren und Language Constructs in der
link:/docs/KERNEL/kernel-documentation-ba-en/index.html[Kernel Language] und den Fields und Groups im referenzierten Document Model unterstützen die im Listing-Element verwendeten <<Computations, Computations>> die Nutzung von <<ListingAdditionalFields, Additional Computation Fields>>.
Die Additional Computation Fields ermöglichen den Zugriff auf Eigenschaften relativ zur Field- oder Group-Instanz der aktuellen Zeile.

=== Additional Computation Fields [[ListingAdditionalFields]]

Die Berechnungen innerhalb des komplexen Listings unterstützen Referenzen auf die folgenden Fields, um Informationen über die Entität der aktuellen Zeile abzurufen:

* `value` – Referenz auf den Wert des aktuellen Fields. Für Groups nicht gefüllt.
* `path` – Referenz auf den Path des aktuellen Fields oder der aktuellen Group.
* `name` – Referenz auf den Namen des aktuellen Fields oder der aktuellen Group.
* `depth` – Referenz auf die Verschachtelungstiefe des aktuellen Fields oder der aktuellen Group innerhalb des Document Models. Root Groups haben `[depth] == 0`.
* `isField` – ergibt _True_, wenn die aktuelle Entität ein Field ist, andernfalls _False_.
* `currentRepetition` – der Wiederholungsindex der aktuellen Entität.
* `repetitions` – der Wiederholungswert der aktuellen Entität.
* `relativeMetadata/...` – Präfix für den Zugriff auf die <<MetadataFieldsInComputations, Metadata>> der aktuellen Entität.
* `relativeAnnotation/...` – Präfix für den Zugriff auf die <<AnnotationFieldsInComputations, Annotations>> der aktuellen Entität.

Darüber hinaus können Referenzen auf die folgenden Fields verwendet werden, um Informationen über die übergeordnete Group der aktuellen Entität abzurufen:

* `currentRepetitionOfParent` – der Wiederholungsindex der übergeordneten Group der aktuellen Entität.
* `repetitionsOfParent` – der Wiederholungswert der übergeordneten Group der aktuellen Entität.
* `parentName` – der Name der übergeordneten Group der aktuellen Entität.
* `parentPath` – der Path der übergeordneten Group der aktuellen Entität.
.Einfache Beispiele für Preconditions mit Additional Computation Fields
[%header, cols="3a,2"]
|===
|Preconditions mit Additional Field|Ergebnis
|``[depth] == 1``
|Gibt `_True_` für jedes Child der Root Group des Document Models zurück.
|``FieldFilled(relativeAnnotation/annotationA)``

|Gibt `_True_` zurück, wenn die aktuelle Entität die Annotation annotationA besitzt.
|===
.Einfache Beispiele für Operationen mit Additional Computation Fields
[%header, cols="3a,2"]
|===
|Operationen mit Additional Field|Ergebnis
|``[value]``
|Gibt den Wert des aktuellen Fields zurück.
|``[relativeMetadata/label]``

|Gibt das Label der aktuellen Entität zurück.
|===
.Fortgeschrittene Beispiele für Preconditions mit Additional Computation Fields
[%header, cols="3a,2"]
|===
|Precondition mit Additional Fields|Ergebnis
|``[parentPath] == "/general/phone/" AND [repetitionsOfParent] < 2``
|Gibt `_True_` für jedes Child der Group /general/phone/ zurück, wenn die Group weniger als 2 Instanzen hat.
|``[repetitionsOfParent] > 1 AND RoundDown ([currentRepetitionOfParent] / 2, 0) != RoundUp([currentRepetitionOfParent] / 2, 0)``

|Gibt `_True_` für jedes zweite Child einer wiederholbaren Group zurück.
|===

== Property Computation [[PropertyComputation]]

Eine Property Computation besteht aus einer Ziel-Property und einem Satz von Computation-Alternativen, die jeweils aus einer Precondition und einer Operation bestehen.
Als Ziel-Property kann eine Vielzahl von Properties festgelegt werden, darunter:

* <<TextProperties, Text Properties>>
* <<BorderProperties, Border Properties>>
* <<TextStylesTab, Text Styles>>

Zusätzlich können die folgenden Properties gesetzt werden:

* *Vertical Alignment:* Definiert die vertikale Ausrichtung des Zellinhalts.
* *Hide Cell:* Ein boolescher Wert. Wenn er auf _True_ gesetzt ist, wird die Zelle vollständig ausgeblendet.
* *Hide Value:* Ein boolescher Wert. Wenn er auf _True_ gesetzt ist, wird der Wert der Zelle ausgeblendet. (Nur für Property Computations in <<ListingColumn, Listing-Spalten>> verfügbar.)
* *Column Span:* Ein numerischer Wert, der die Anzahl der Spalten definiert, die die Zelle überspannt. (Nur für Property Computations in <<ListingColumn, Listing-Spalten>> verfügbar.)


Die <<ListingAdditionalFields, Additional Computational Fields>> können auch in den Preconditions und Operations von Property Computations verwendet werden.

== Group Property Computation [[GroupPropertyComputation]]

Eine Group Property Computation wendet Properties auf alle Listing-Zeilen an, die einer ausgewählten Group-Instanz entsprechen.
Sie besteht aus einer Ziel-Property, einer Group-Instanz und einem Satz von Computation-Alternativen, die jeweils aus einer Precondition und einer Operation bestehen.

Derzeit kann nur *Hide Group* als Ziel-Property für Group Property Computations verwendet werden.
Wenn die Computation-Alternativen zu _True_ ausgewertet werden, werden alle zur ausgewählten Group-Instanz gehörenden Zeilen ausgeblendet.

WARNING: Die Precondition darf nur für Fields und Groups innerhalb des ausgewählten Group Path zu „true" ausgewertet werden.

== Anhänge [[ListingAttachment]]

Anhänge im Listing-Element werden in das generierte PDF eingebunden, wenn die ausgewählte Group Attachment-Groups enthält. Diese Anhänge werden am Ende des PDFs hinzugefügt, nachdem der gesamte Print Model-Inhalt gerendert wurde. Jeder Anhang beginnt auf einer neuen Seite.

=== Rendern von Anhängen

Anhänge können auf zwei Arten aufgelöst werden:

- **Eingebetteter Anhang**: Der Inhalt des Anhangs ist in den Dokumentdaten eingebettet.
- **Referenzierter Anhang**: Referenzierung eines Anhangs durch Angabe der Attachment-ID. Der AttachmentProvider verwendet diese ID, um den Anhanginhalt zur Renderzeit bereitzustellen.

==== Renderverhalten:
- Wenn der Anhanginhalt vorhanden ist, wird er gerendert.
- Wenn die Attachment-ID vorhanden ist, wird der referenzierte Anhang gerendert.
- Wenn sowohl Inhalt als auch ID angegeben sind, hat der Inhalt Vorrang und wird gerendert.

Um referenzierte Anhänge zu ermöglichen, müssen Sie den link:/docs/PRINT_ENGINE/print-technical-documentation/index.html#attachment_provider[AttachmentProvider] verwenden.

- **Attachment Fields**: Im gerenderten Listing werden alle Attachment Fields angezeigt. Das Inhaltsfeld wird jedoch als Link dargestellt, der auf den gerenderten Anhang verweist.
- **Bildgröße**: Die Bildgröße wird so skaliert, dass sie die volle Seitenbreite ausfüllt.
- **Unterstützte Anhangtypen**:
  * Bilder: `png`, `jpg`
  * PDFs: `pdf`

[NOTE]
====
Wenn der Anhangtyp nicht unterstützt wird, wird das Inhaltsfeld im Listing-Ergebnis nicht angezeigt und der Anhang wird nicht gerendert.
====

[CAUTION]
====
Es wird dringend empfohlen, **referenzierte Anhänge** zu verwenden, da A12 **eingebettete Anhänge** nicht mehr vollständig unterstützt.
