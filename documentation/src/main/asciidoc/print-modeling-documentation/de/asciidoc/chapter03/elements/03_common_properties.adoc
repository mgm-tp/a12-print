= Gemeinsame Eigenschaften von Print Model Elements [[CommonProperties]]

== Detail View [[DetailView]]

Die Detail View ermöglicht die Bearbeitung der Eigenschaften jedes einzelnen Elements.
Die verfügbaren Modellierungsoptionen in der Detail View hängen vom Typ des ausgewählten Elements ab.

Die Detail View besitzt keine Schaltfläche „Save", da jede Änderung automatisch in der <<CommitChangesTab, Commit-Historie>> gespeichert wird.
Klicken Sie einfach auf „Close" in der oberen rechten Ecke der Detail View oder wählen Sie das nächste Element in der Editor Stage aus.

image::chapter03/03_text_detail_view.png[Element Detail View,title="Element Detail View"]

=== Input Source [[InputSource]]
Diese Funktion ermöglicht es Benutzern, die Quelle von Werten explizit zu definieren. Dadurch werden Datenklarheit und Eingabekontrolle verbessert.

Durch die Angabe der Wertequelle wird die Mehrdeutigkeit zwischen nicht gesetzten Werten und Standardwerten aufgelöst. Außerdem werden die Kontexte verdeutlicht, die den Wert beeinflussen. Benutzer können fundierte Entscheidungen treffen, indem sie den genauen Ursprung der Werte in ihren Ergebnissen verstehen. Verwechslungen oder fehlerhafte Annahmen werden so vermieden.

Es gibt vier Arten von Quellen, die auf Fields angewendet werden:

* *Default*: Der Standardwert wird für das Field verwendet
* *Input*: Der Wert wird vom Benutzer bereitgestellt
* *Unset*: Es wird kein Wert zugewiesen
* *Inherited*: Der Wert wird vom übergeordneten Element geerbt

== Hide Conditions [[HideConditions]]

Hide Conditions ermöglichen die Definition von Bedingungen, die Elemente im resultierenden PDF-Dokument ausblenden.
Die Hide Conditions können bearbeitet werden, indem Sie mit der rechten Maustaste auf ein Element klicken und die Option „Hide Conditions" auswählen.
Die Bedingungen werden als <<Computations>> in der Syntax der link:/docs/KERNEL/kernel-documentation-ba-en/index.html[Kernel Language] geschrieben.
Es wird erwartet, dass die Bedingung einen booleschen Wert zurückgibt, wobei _True_ dazu führt, dass das Element ausgeblendet wird.

Wenn ein Element im resultierenden PDF-Dokument ausgeblendet wird, rücken die darunterliegenden Elemente so weit wie möglich nach oben.

image::chapter03/03_hide_conditions_detail_view.png[Hide Conditions Detail View,title="Hide Conditions Detail View"]

=== Beispiel [[HideConditionsExample]]

Betrachten Sie das unten dargestellte Beispiel, das im <<MarginLayoutFigures, Margin-Layout-Beispiel>> eingeführt wurde.

* Wenn Element *A* durch eine Hide Condition ausgeblendet wird, verschieben sich alle darunterliegenden Elemente um eine Strecke nach oben, die der Höhe von Element *A* und dessen unterem Rand entspricht.
* Wenn Element *B* ausgeblendet wird, wird kein anderes Element verschoben.
Element *D* kann nicht nach oben verschoben werden, da es durch Element *C* und dessen unteren Rand blockiert wird.
* Wenn Element *C* ausgeblendet wird, wird kein anderes Element verschoben.
Element *D* kann nicht nach oben verschoben werden, da es durch Element *B* und dessen unteren Rand blockiert wird.
* Wenn Element *B* und *C* ausgeblendet werden, verschiebt sich Element *D* um eine Strecke nach oben, die der Höhe und dem unteren Rand von Element *B* entspricht.
* Wenn Element *A*, *B* und *C* ausgeblendet werden, verschiebt sich Element *D* nach oben an die ursprüngliche Position von Element *A*.

== Computations [[Computations]]

Computations in Print Models verwenden die Syntax der link:/docs/KERNEL/kernel-documentation-ba-en/index.html[Kernel Language], um Werte dynamisch zu berechnen oder Bedingungen auszuwerten.
Je nach Kontext dienen Computations im Print Model unterschiedlichen Zwecken:

=== Bedingungen

Werden verwendet, um Inhalte bedingt anzuzeigen oder auszublenden. Diese können eingesetzt werden in:

* <<HideConditions, Hide Conditions>> – um Elemente bedingt auszublenden
* <<Switch, Switch Cases>> – um bedingt unterschiedliche Inhalte anzuzeigen
* <<WatermarkTab, Watermarks>> – um Wasserzeichen bedingt anzuzeigen

=== Computation Alternatives

Werden verwendet, um dynamische Werte zu berechnen. Diese können eingesetzt werden in:

* <<Calculation, Calculation Elements>> – um dynamische Werte zu berechnen und anzuzeigen
* <<Listing, Listing Elements>> – um Zellwerte und -eigenschaften zu berechnen

Jede Computation Alternative besteht aus:

Precondition:: Eine Bedingung, die zu _True_ ausgewertet werden muss, damit die Operation angewendet wird. Wenn keine Precondition angegeben ist, wird die Operation immer angewendet.
Operation:: Der Ausdruck, der den Ergebniswert berechnet.

Die Computation Alternatives werden der Reihe nach ausgewertet. Die erste mit einer zutreffenden Precondition (oder ohne Precondition) wird verwendet.

=== Referenzierung von Document-Model-Daten

In Computations können Sie Fields und Groups aus dem Document Model über deren Paths referenzieren:

----
[CustomerDM/customer/firstName]
----

=== Document-Model-Metadaten-Fields [[MetadataFieldsInComputations]]

Neben der Referenzierung von Fields und Groups des Document Model können Sie auch auf Metadaten-Eigenschaften von Document-Model-Elementen zugreifen. Verwenden Sie dazu das Präfix `metadata/...`.

----
metadata/<element-path>/<metadata-field>
----

Um beispielsweise auf die `label`-Metadaten eines Fields unter `/customer/firstName` zuzugreifen:

----
[metadata/customer/firstName/label]
----

Dies gibt das lokalisierte Label des Fields zurück, z. B. „First Name".

Sie können auch auf Annotations von Document-Model-Elementen zugreifen. Verwenden Sie dazu das Präfix `annotations/...`:

----

----

Beispiel:

----

----

== Seitenumbruchverhalten [[PageBreakBehavior]]
Das Seitenumbruchverhalten ermöglicht es Benutzern zu definieren, wie ein Element mit Seitenumbrüchen im resultierenden PDF-Dokument interagiert.
Diese Einstellung ist nur auf dem <<SegmentTab, Segment Tab>> verfügbar. Um sie zu bearbeiten, doppelklicken Sie auf das Element im <<LayoutMode, Layout Mode>>, um die Detail View zu öffnen. Die Optionen für das Seitenumbruchverhalten befinden sich unter den Seitenumbruch-Einstellungen.

image::chapter03/03_page_break_behavior_detail_view.png[Detail View für Seitenumbruchverhalten,title="Detail View für Seitenumbruchverhalten"]

Die <<InputSource, Input Source>> wird verwendet, um die Quelle für den Wert des Seitenumbruchverhaltens festzulegen. Es stehen drei Quellen zur Verfügung:

* *Default*: Der Standardwert wird angewendet. Der Standardwert ist *Allow*.
* *Input*: Der Benutzer kann zwischen den beiden unten beschriebenen Verhaltensoptionen wählen.
* *Inherited*: Der Wert wird vom übergeordneten Element geerbt. Dies gilt nur für Elemente innerhalb von Container-Elementen (Bounding Box/Area/Switch).

Die Optionen für das Seitenumbruchverhalten sind:

Allow:: Das Element kann über Seiten hinweg aufgeteilt werden.

Avoid:: Das Element wird nicht über Seiten hinweg aufgeteilt.
+
* *Für Container-Elemente* (Bounding Box/Area/Switch): Wenn das Element (einschließlich Abstände zwischen untergeordneten Elementen und untergeordneten Elementen, die ebenfalls auf „Avoid" gesetzt sind) auf einen Seitenumbruch fällt, wird das gesamte Element auf die nächste Seite verschoben – auch wenn es dort nicht vollständig Platz findet.
* *Für eigenständige Elemente*: Wenn das Element auf einen Seitenumbruch fällt, wird es auf die nächste Seite verschoben, um eine Aufteilung zu vermeiden. Passt es auch auf die nächste Seite nicht, verbleibt es an seiner aktuellen Position.

NOTE: Bei wiederholbaren Areas und Switch-Elementen wird das Seitenumbruchverhalten *nicht* auf das gesamte Element angewendet, sondern auf jede einzelne Wiederholung bzw. jeden Case. Das bedeutet: Wenn eine Area oder ein Switch auf *Avoid* gesetzt ist, versucht jede Wiederholung bzw. jeder Case, eine Aufteilung über Seiten hinweg zu vermeiden. Unterschiedliche Wiederholungen bzw. Cases können jedoch auf verschiedenen Seiten landen.

Wenn ein Element auf *Avoid* gesetzt ist, wird dies durch ein kleines Symbol in der oberen rechten Ecke des Elements in der Layout Editor Stage angezeigt.

image::chapter03/03_page_break_behavior_indicator.png[Indikator für Seitenumbruchverhalten,title="Indikator für Seitenumbruchverhalten"]

=== Standard-Input-Source für neue Elemente
* In der Segment-Stufe: Beim Erstellen eines neuen Elements wird die Quelle des Seitenumbruchverhaltens auf *Default* gesetzt.
* In der Stufe von Container-Elementen (Bounding Box/Area/Switch): Beim Erstellen eines neuen Elements wird die Quelle des Seitenumbruchverhaltens auf *Inherited* gesetzt und referenziert das Seitenumbruchverhalten des umgebenden Container-Elements.
