= Gemeinsame Eigenschaften von Print Model Elements [[CommonProperties]]

== Detail View [[DetailView]]

Die Detail View ermöglicht das Bearbeiten der Eigenschaften jedes einzelnen Elements.
Die in der Detail View verfügbaren Modellierungsoptionen werden durch den Typ des ausgewählten Elements bestimmt.

Die Detail View besitzt keine Schaltfläche Save, da jede Änderung automatisch in der <<CommitChangesTab, Commit-Historie>> gespeichert wird.
Klicken Sie einfach auf „Close" in der oberen rechten Ecke der Detail View oder wählen Sie das nächste Element in der Editor Stage aus.

image::chapter03/03_text_detail_view.png[Element Detail View,title="Element Detail View"]

=== Input Source [[InputSource]]
Diese Funktion ermöglicht es, die Quelle von Werten explizit zu definieren. Dadurch werden Datenklarheit und Eingabekontrolle verbessert.

Durch die Angabe der Wertquelle wird die Mehrdeutigkeit zwischen nicht gesetzten und Standardwerten aufgelöst. Außerdem werden die Kontexte verdeutlicht, die den Wert beeinflussen. Sie können fundierte Entscheidungen treffen, indem Sie den genauen Ursprung der Werte in Ihren Ergebnissen nachvollziehen. So werden Verwechslungen oder fehlerhafte Annahmen vermieden.

Es gibt vier Quelltypen, die auf Fields angewendet werden:

* *Default*: Der Standardwert wird für das Field verwendet.
* *Input*: Der Wert wird vom Benutzer angegeben.
* *Unset*: Es wird kein Wert zugewiesen.
* *Inherited*: Der Wert wird vom übergeordneten Element geerbt.

== Hide Conditions [[HideConditions]]

Hide Conditions ermöglichen die Definition von Bedingungen, die Elemente in der resultierenden PDF-Datei ausblenden.
Die Hide Conditions können durch Rechtsklick auf ein Element und Auswahl der Option „Hide Conditions" bearbeitet werden.
Die Bedingungen werden als <<Computations>> in der Syntax der link:/docs/KERNEL/kernel-documentation-ba-en/index.html[Kernel Language] geschrieben.
Es wird erwartet, dass die Bedingung einen booleschen Wert zurückgibt, wobei _True_ dazu führt, dass das Element ausgeblendet wird.

Wenn ein Element im resultierenden PDF-Dokument ausgeblendet wird, rücken die darunterliegenden Elemente so weit wie möglich nach oben.

image::chapter03/03_hide_conditions_detail_view.png[Hide Conditions Detail View,title="Hide Conditions Detail View"]

=== Beispiel [[HideConditionsExample]]

Betrachten Sie das unten dargestellte Beispiel, das im <<MarginLayoutFigures, Margin-Layout-Beispiel>> eingeführt wurde.

* Wenn Element *A* durch eine Hide Condition ausgeblendet wird, rücken alle darunterliegenden Elemente um eine Strecke nach oben, die der Höhe von Element *A* und seinem unteren Rand entspricht.
* Wenn Element *B* ausgeblendet wird, wird kein anderes Element verschoben.
Element *D* kann nicht nach oben rücken, da es durch Element *C* und dessen unteren Rand blockiert wird.
* Wenn Element *C* ausgeblendet wird, wird kein anderes Element verschoben.
Element *D* kann nicht nach oben rücken, da es durch Element *B* und dessen unteren Rand blockiert wird.
* Wenn Element *B* und *C* ausgeblendet werden, rückt Element *D* um eine Strecke nach oben, die der Höhe und dem unteren Rand von Element *B* entspricht.
* Wenn Element *A*, *B* und *C* ausgeblendet werden, rückt Element *D* an die ursprüngliche Position von Element *A*.

== Computations [[Computations]]

Computations in Print Models verwenden die Syntax der link:/docs/KERNEL/kernel-documentation-ba-en/index.html[Kernel Language], um Werte dynamisch zu berechnen oder Bedingungen auszuwerten.
Je nach Kontext dienen Computations im Print Model unterschiedlichen Zwecken:

=== Bedingungen

Werden verwendet, um Inhalte bedingt ein- oder auszublenden. Dies kann eingesetzt werden in:

* <<HideConditions, Hide Conditions>> – um Elemente bedingt auszublenden
* <<Switch, Switch Cases>> – um bedingt unterschiedliche Inhalte anzuzeigen
* <<WatermarkTab, Watermarks>> – um bedingt Wasserzeichen anzuzeigen

=== Computation Alternatives

Werden verwendet, um dynamische Werte zu berechnen. Dies kann eingesetzt werden in:

* <<Calculation, Calculation Elements>> – um dynamische Werte zu berechnen und anzuzeigen
* <<Listing, Listing Elements>> – um Zellwerte und -eigenschaften zu berechnen

Jede Computation Alternative besteht aus:

Precondition:: Eine Bedingung, die zu _True_ ausgewertet werden muss, damit die Operation angewendet wird. Wird keine Precondition angegeben, wird die Operation immer angewendet.
Operation:: Der Ausdruck, der den Ergebniswert berechnet.

Die Computation Alternatives werden der Reihe nach ausgewertet. Die erste mit einer zutreffenden Precondition (oder ohne Precondition) wird verwendet.

=== Referenzierung von Document-Model-Daten

In Computations können Sie Fields und Groups aus dem Document Model über ihre Pfade referenzieren:

----
[CustomerDM/customer/firstName]
----

=== Metadaten-Fields des Document Model [[MetadataFieldsInComputations]]

Zusätzlich zur Referenzierung von Fields und Groups des Document Model können Sie auf Metadaten-Eigenschaften von Document-Model-Elementen über das Präfix `metadata/...` zugreifen.

----
metadata/<element-path>/<metadata-field>
----

Um beispielsweise auf die `label`-Metadaten eines Fields unter `/customer/firstName` zuzugreifen:

----
[metadata/customer/firstName/label]
----

Dies würde das lokalisierte Label des Fields zurückgeben, z. B. „First Name".

Sie können auch auf Annotations von Document-Model-Elementen über das Präfix `annotations/...` zugreifen:

== Seitenumbruchverhalten [[PageBreakBehavior]]
Das Seitenumbruchverhalten ermöglicht es, zu definieren, wie ein Element mit Seitenumbrüchen im resultierenden PDF-Dokument interagiert.
Diese Einstellung ist nur auf dem <<SegmentTab, Segment Tab>> verfügbar. Um sie zu bearbeiten, doppelklicken Sie auf das Element im <<LayoutMode, Layout Mode>>, um die Detail View zu öffnen. Die Optionen für das Seitenumbruchverhalten befinden sich unter den Seitenumbruch-Einstellungen.

image::chapter03/03_page_break_behavior_detail_view.png[Seitenumbruchverhalten Detail View,title="Seitenumbruchverhalten Detail View"]

Die <<InputSource, Input Source>> wird verwendet, um die Quelle für den Wert des Seitenumbruchverhaltens zu definieren. Es stehen drei Quellen zur Verfügung:

* *Default*: Der Standardwert wird angewendet. Der Standardwert ist *Allow*.
* *Input*: Der Benutzer kann zwischen den beiden unten beschriebenen Verhaltensoptionen wählen.
* *Inherited*: Der Wert wird vom übergeordneten Element geerbt. Dies gilt nur für Elemente innerhalb von Container-Elementen (Bounding Box/Area/Switch).

Die Optionen für das Seitenumbruchverhalten sind:

Allow:: Das Element kann über Seiten hinweg aufgeteilt werden.

Avoid:: Das Element wird nicht über Seiten hinweg aufgeteilt.
+
* *Für Container-Elemente* (Bounding Box/Area/Switch): Wenn das Element (einschließlich Abständen zwischen Kindelementen und Kindelementen, die ebenfalls auf „Avoid" gesetzt sind) auf einen Seitenumbruch fällt, wird das gesamte Element auf die nächste Seite verschoben – auch wenn es dort nicht vollständig hineinpasst.
* *Für eigenständige Elemente*: Wenn das Element auf einen Seitenumbruch fällt, wird es auf die nächste Seite verschoben, um eine Aufteilung zu vermeiden. Passt es auch auf die nächste Seite nicht, verbleibt es an seiner aktuellen Position.

NOTE: Bei wiederholbaren Areas und Switch-Elementen wird das Seitenumbruchverhalten *nicht* auf das gesamte Element angewendet, sondern auf jede einzelne Wiederholung bzw. jeden einzelnen Case. Das bedeutet: Wenn eine Area oder ein Switch auf *Avoid* gesetzt ist, versucht jede Wiederholung bzw. jeder Case, eine Aufteilung über Seiten hinweg zu vermeiden. Unterschiedliche Wiederholungen bzw. Cases können jedoch auf verschiedenen Seiten landen.

Wenn ein Element auf *Avoid* gesetzt ist, wird dies durch ein kleines Symbol in der oberen rechten Ecke des Elements in der Layout Editor Stage angezeigt.

image::chapter03/03_page_break_behavior_indicator.png[Seitenumbruchverhalten-Indikator,title="Seitenumbruchverhalten-Indikator"]

=== Standard-Input-Source für neue Elemente
* In der Segment-Ebene: Beim Erstellen eines neuen Elements wird die Input Source des Seitenumbruchverhaltens auf *Default* gesetzt.
* In der Ebene von Container-Elementen (Bounding Box/Area/Switch): Beim Erstellen eines neuen Elements wird die Input Source des Seitenumbruchverhaltens auf *Inherited* gesetzt und referenziert das Seitenumbruchverhalten des umgebenden Container-Elements.

CAUTION: Das Seitenumbruchverhalten ist im <<legacy_rendering_mode, Legacy Rendering Mode>> nicht verfügbar.
