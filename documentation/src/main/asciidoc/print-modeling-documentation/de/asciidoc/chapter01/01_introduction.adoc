= Einführung und Konzepte

Der Print Model Editor ist Bestandteil des Simple Model Editor und ermöglicht es Fachexperten und Analysten, Print Models zu erstellen und zu bearbeiten. Diese Modelle dienen als Vorlagen zur Erzeugung von PDF-Dokumenten aus Daten der A12 Platform.

Print Models beschreiben Layout, Gestaltung und Inhalt der resultierenden PDF-Dokumente.
Der Print Model Editor unterscheidet sich von einem herkömmlichen Texteditor durch seine Ausrichtung auf die Einbindung _dynamischer Inhalte_ aus der A12 Platform.
Print Models ermöglichen sowohl einfache Dateneinbindungen als auch komplexe dynamische Berechnungen auf Basis der eingefügten Daten.
Beispiele reichen von Inline-Texteinfügungen und Tabellen über Elementwiederholungen und regelbasiertes Ausblenden von Elementen bis hin zu Auflistungen mit vollständig anpassbaren Inhalten und Styles.

[ACCESSIBILITY_HINT]
====
icon:universal-access[] *Barrierefreiheitshinweis*
Die Print Engine erzeugt PDF-Dokumente mit getaggten Elementen für Barrierefreiheitssoftware wie Screenreader, die den Standards PDF/UA und PDF/A-3a entsprechen.

Um sicherzustellen, dass das resultierende PDF-Dokument vollständig diesen Standards entspricht, muss der Modellersteller die in dieser Dokumentation enthaltenen Barrierefreiheitshinweise befolgen. Diese sind für die Konformität verpflichtend. Werden sie nicht umgesetzt, erfüllt das PDF weder PDF/UA noch PDF/A-3a.
====

== Installation
Der Print Model Editor ist Bestandteil des Simple Model Editor.
Hinweise zur Installation des Simple Model Editor finden Sie im „Quick Start Guide" auf getA12 unter „Modeling".

NOTE: Zum Erstellen oder Bearbeiten eines Print Model verwenden Sie den Simple Model Editor (SME) in Version `11.5.0` oder höher, der ab A12 Version `2024.06-ext4` oder höher bereitgestellt wird.

== Migration bestehender Modelle [[MigratingModels]]

Bei der Installation einer neuen Version des Simple Model Editor und damit des Print Model Editor kann es erforderlich sein, bestehende Print Models zu migrieren.

In den meisten Fällen kann der Simple Model Editor die Versionsaktualisierung selbständig durchführen.
Weitere Informationen finden Sie in der Dokumentation des Simple Model Editor.

[NOTE]
====
Seit Print Model Version `2.1.0` übernimmt der SME die Migration automatisch.
Enthält ein Workspace im SME alte Modelle, die migriert werden müssen, erscheint eine Fehlermeldung mit entsprechenden Hinweisen.
Klicken Sie auf die Schaltfläche `Resolve All Issues`, um die Modelle automatisch zu aktualisieren.
====

[NOTE]
====
Print Model-Dateien, die älter als Version `2.1.0` sind, müssen zunächst mit dem Java-basierten print-shell-Tool migriert werden.
Folgen Sie den link:/docs/PRINT_ENGINE/print-technical-documentation/index.html#legacy_migration[Migrationsanweisungen für print-shell].
====

[WARNING]
====
Bei der Migration eines Print Model auf eine neue Version im SME können nicht committete Änderungen in `.wal`-Dateien nach der Migration ungültig werden.
Bitte committen Sie alle ausstehenden Änderungen, *bevor* Sie das Modell in einer neueren SME-Version öffnen und migrieren, um Datenverlust zu vermeiden.
====

== Print Model [[PrintModelIntro]]
Ein Print Model dient als Vorlage für die PDF-Darstellung eingefügter Documents.

Die Struktur des resultierenden PDF-Dokuments wird durch die im <<SegmentTab>> modellierten Segments definiert.

Das PDF kann durch die Modellierung von Sections und Watermarks im <<SectionTab>> und im <<WatermarkTab>> weiter angepasst werden.

Im <<TextStylesTab>> definierte Text Styles beeinflussen ebenfalls das Erscheinungsbild des PDF-Dokuments.

Bei der Modellierung von <<SegmentTab, Segments>>, <<SectionTab, Sections>> und <<WatermarkTab, Watermarks>> werden Print Model Elements verwendet, um den Inhalt des PDF-Dokuments zu definieren.
Diese Elemente werden der <<EditorStage>> hinzugefügt und im Millimeterraster positioniert. Die individuellen Einstellungen jedes Elements können wie in <<PrintModelElement>> beschrieben modelliert werden.

[ACCESSIBILITY_HINT]
====
icon:universal-access[] *Barrierefreiheitshinweis*

Bitte beachten Sie, dass es derzeit nicht möglich ist, die Lesereihenfolge von Elementen für Screenreader manuell festzulegen. Sollten Sie diese Funktion in Ihrem Projekt benötigen, wenden Sie sich bitte an das Print Engine-Team, damit es diese für zukünftige Updates berücksichtigen kann.
====

Print Model Elements können Referenzen auf Daten aus Document Models nutzen, um dynamische Inhalte im PDF darzustellen.
Zu diesem Zweck können Sie im <<SchemaTab>> ein Document Model referenzieren.

== Konzepte
=== Positionierung & Layout [[PositioningLayout]]

<<PrintModelElement, Print Model Elements>> werden auf einem Millimeterraster positioniert.
Jedes Element hat eine benutzerdefinierte Breite und eine anfängliche Höhe basierend auf seinem vordefinierten Inhalt.
Enthält ein Element dynamische Inhalte, kann sich seine Höhe ändern, wodurch der darunterliegende Inhalt nach unten verschoben werden kann.

NOTE: Das Millimeterraster des Print Model Editor weist auf Ihrem Bildschirm möglicherweise keine exakten Maße auf. Die Anzeigemaße hängen von Ihrem Displaytyp ab und haben keinen Einfluss auf das resultierende PDF-Dokument.

Basierend auf ihren relativen Positionen definieren Elemente einen sogenannten _unteren Rand_ (Bottom Margin).
Dieser Wert legt den Bereich unterhalb eines Elements fest, der bei der Neupositionierung und bei Elementkollisionen freigehalten wird.
In manchen Fällen ist auch ein _oberer Rand_ (Top Margin) erforderlich.

==== Beispiel

In den <<MarginLayoutFigures, folgenden Abbildungen>> wird ein Szenario dargestellt, in dem beide Ränder notwendig sind, um das erwartete Layout bei der Einfügung dynamischer Inhalte stabil zu halten.
Platziert der Benutzer die Elemente *A*, *B*, *C* und *D* wie in der linken Abbildung, werden die in der rechten Abbildung dargestellten Ränder automatisch vom Editor erzeugt.

Jedes Element besitzt einen _unteren Rand_, der den Leerraum zwischen den Elementen stabil hält.
Für Element *B* wird ein oberer Rand erzeugt, da der untere Rand von Element *A* nur bis zu Element *C* reicht.
Dadurch bleibt der Leerraum zwischen Element *A* und Element *B* teilweise unbedeckt.
Deshalb wird für Element *B* ein _oberer Rand_ erzeugt, der diesen Bereich abdeckt.

=== Vorlagen und Einstellungen
Sie können Print Model References als <<PrintModelTemplates,Vorlagen>> in anderen Print Models verwenden.
Damit können Sie Bereiche mit fester Höhe und statischem Layout definieren und Print Models erstellen, die verschiedenen Normen entsprechen (z. B. DIN-Normen).

Die verfügbaren Schriftarten werden als Workspace-Ressourcen bereitgestellt und können im Print Model bei der Konfiguration von <<TextStylesTab, Text Styles>> ausgewählt werden.

=== Fragment Models
Inhalte, die in mehr als einem Print Model verwendet werden, können einmalig in einem <<FragmentModels, Print Fragment Model>> definiert und von jedem Print Model referenziert werden, das sie benötigt.
Segments, Sections, Watermarks, Text Styles und einzelne Print Model Elements können als solche wiederverwendbaren Fragments definiert werden.

=== Dynamische Inhalte
Print Model Elements können Referenzen auf Daten aus Document Models nutzen, um dynamische Inhalte im PDF darzustellen.
Zu diesem Zweck können Sie in Ihrem Print Model ein Document Model referenzieren.
Dadurch können Sie Daten aus Documents, die auf diesem Document Model basieren, auf verschiedene Weisen als dynamische Inhalte einbinden:

* Field References
* Computations
* Expressions

Print Model Elements wie Tabellen und Auflistungen können zur Anzeige wiederholbarer Daten verwendet werden.
Beim Rendern der Preview werden auf Basis der vorgenommenen Modellierungseinstellungen automatisch Zeilen für die wiederholbaren Daten erzeugt.

=== Preview [[PreviewIntro]]
Die <<Preview>> kann verwendet werden, um eine PDF-Vorschau Ihres Modells zu erzeugen.
Wurden im Modell dynamische Inhalte referenziert, können Sie ein Document für die Preview auswählen, das dann als Quelle für die dynamischen Inhalte dient.

== Änderungen committen [[CommittingChanges]]

Der PME arbeitet *direkt* auf dem ausgewählten Workspace.
Änderungen an den Workspace-Dateien werden vom PME automatisch neu geladen.
Änderungen im PME werden in temporären `.wal`-Dateien gespeichert.
Diese Dateien dienen als Änderungshistorie des Editors und werden von Funktionen wie _Undo_ und _Redo_ genutzt.

Print Models mit gespeicherten `.wal`-Dateien werden im Workspace Explorer des Simple Model Editor mit einem Symbol gekennzeichnet: „The model has uncommitted changes".

Um vorgenommene Änderungen zu finalisieren, kann der Benutzer sie im <<CommitChangesTab>> in das Print Model _committen_.
Dabei werden die Änderungen auf das Print Model angewendet, das resultierende Modell validiert und bei Erfolg die `.wal`-Datei gelöscht sowie das Print Model im Workspace überschrieben.

[NOTE]
====
Dieses Verfahren sichert auch temporäre Änderungen bei Systemabstürzen, beim Schließen des Editors oder bei Validierungsproblemen.
Jede Änderung des Benutzers wird direkt im Workspace abgebildet, was bei Supportanfragen und Fehlerberichten hilfreich ist.
Bitte fügen Sie bei solchen Anfragen Ihr Print Model und alle relevanten `.wal`-Dateien bei.
====
