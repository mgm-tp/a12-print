[#print_model_usage]
= Print Model Usage

If the Print Model has been modeled correctly and the Print Engine has been properly integrated into the A12 Full Stack application (link:/docs/PRINT_ENGINE/print-technical-documentation/index.html#a12_fullstack_integration[A12 Full Stack Integration]),
Form models or Overview models can now be used to start printing:

. link:/docs/SME/sme-fm-ba-docs/index.html#txt:detail:button[Form Model Event Button]:
Create a Event Button in the Form Model with the event name *event_print* and an annotation with the name *print_model*, which contains the Print Model name as value
. link:/docs/SME/sme-om-ba-docs/index.html#row-action[Overview Model Row Button]: Create a Row Action Event Button on the Form with the event name *event_print* and an annotation with the name *print_model*, which contains the Print Model name as value

In a Form in the link:/docs/overall/preview_app/index.html[Preview App] the document is automatically validated and saved before it is printed to ensure that the current values are included in the PDF.

During print in the Form and Overview in the link:/docs/overall/preview_app/index.html[Preview App] a loading spinner will be visible across the entire application.

To ensure that static images and custom fonts are displayed correctly in the PDF generated by the Preview app, they must be located in specific folders:

* static images: `resources/static-images`
* custom fonts: `resources/fonts`

[CAUTION]
====
The print model itself can be updated while the Preview App is running. This is not currently the case for static images and fonts. Therefore, if a new static image or font is added to the print model, the Preview App must currently be restarted.
====
