== Changes

=== Engine Runtime

Print Models can now reference Print Fragment Models, which hold reusable content such as Segments, Sections, Watermarks, Text Styles and single Elements.
To print such a Print Model, the new method `PrintJobManager.PrintJobManagerApi.loadPrintFragmentModel(String id)` must be implemented.
Print Models that do not reference a Print Fragment Model are not affected.
See <<load_print_fragment_model, Loading Print Fragment Models>> for details.

*Migration:* Not needed

=== Print Model Api Utils

==== TypeScript

`PrintModelValidatorOptions.references` accepts three new catalogs next to `documentModels`, each optional and each switching on the reference validation that needs it:

[source,typescript]
----
const { result, report } = marshaller.deserialize(rawJson, {
    references: {
        documentModels: [myDocumentModel],
        fragmentModels: [myPrintFragmentModel],
        typesettingModelIds: ["my-typesetting"],
        printModelIds: ["my-din-template"],
    }
});
----

* `fragmentModels`: the Print Fragment Models used by the Print Model. Fragments that cannot be resolved are reported as errors, and the field paths of the used Fragments are validated against `documentModels`.
* `typesettingModelIds`: the ids of the available Typesetting Models. A Text Style naming an unknown one is reported as a warning.
* `printModelIds`: the ids of the available Print Models, for example DIN templates.

The Model References declared in `header.modelReferences` are now validated against these catalogs.
This also affects callers that only pass `documentModels`: a Document Model Reference naming a Document Model outside the supplied catalog now produces an error that did not occur before.

See <<print_model_marshaller>> for details.

*Migration:* Not needed
